# OV13855 A4 整页画质诊断

本工具用于固定机位、固定 A4 纸张与固定光照下的画质对照。测试目标是普通正文的一次整页识别。距离可调，但裁切页面的距离不参与最终推荐。

## Evidence boundaries

ISP 输出的 NV12 已经过硬件 ISP，不是传感器 Bayer RAW。诊断保存的单帧 PNG 表示未经过 LIRA 软件合并、降噪及白平衡和数字提亮的图像。

中心与四角的裁剪仅用于检查相同纸面文字。距离变化后应重新标注区域，不能继续沿用旧的相机像素坐标。局部清晰和局部 OCR 成功不能替代 A4 整页验收。

OCR 评分需要该页的正确正文。OCR 输出本身不能充当参考答案；没有参考正文时仅做图像与检测输入检查，不报告字符错误率或推荐改善配置。

## Board prerequisites

- 使用板上的现有 Python 虚拟环境、OpenCV、NumPy、v4l2-ctl 和 media-ctl；无需安装桌面环境。RKNN 仅在板上 OCR 命令中使用。
- 记录 LIRA 用户服务原先是否运行。采集前人工暂停服务，结束后恢复原先状态；不要让诊断与生产采集同时控制摄像头。
- 核对媒体拓扑和传感器控制范围，记录节点、实际协商格式、距离、灯光、纸张字号、方向及整页覆盖情况。
- 使用独立实验目录保存样张和报告，通过 SCP 传回电脑。大体积 NV12 和图片不提交到仓库。

## Experiment sequence

### 抓图命令

在板上 `/home/orangepi/lira/device` 中使用现有 `.venv`。先查询，核对传感器和采集节点：

```bash
systemctl --user stop lira
# 如果服务原先在运行，退出这个 shell 时恢复；原先停止时不要设置此 trap。
trap 'systemctl --user start lira' EXIT
.venv/bin/python -m lira.diagnostics.camera_quality inspect
```

将下面的 `DISTANCE_CM` 替换为实际镜头到纸面的距离。`--full-page` 是操作者的确认，工具不会自动判定纸张完整入镜。场景标签中记录光照、字号和纸张方向。

```bash
.venv/bin/python -m lira.diagnostics.camera_quality baseline \
  --scene a4-body-fixed --distance-cm DISTANCE_CM --full-page \
  --output /home/orangepi/lira/camera-experiments
.venv/bin/python -m lira.diagnostics.camera_quality capture \
  --scene a4-body-fixed --distance-cm DISTANCE_CM --full-page \
  --vblank 3300 --exposure 6400 --gain 128 --warmup 5 --frames 3 \
  --output /home/orangepi/lira/camera-experiments
```

上述参数来自当前控制状态，仅用于起始对照，并非推荐配置。退出码为零且 `manifest.json` 的 `valid` 为 true 才表示采集与恢复均成功；失败目录也保留，不要混入有效实验。

普通用户可能无法读取其他用户的 `/proc` 文件描述符。报告会记录检查缺口，不能宣称已排除所有外部占用；仍须暂停摄像头与 3A 控制程序，并检查开流和控制稳定性。

电脑上可通过 `scp -r lira:/home/orangepi/lira/camera-experiments <本地实验目录>` 取回样张。每轮先查看整图是否完整覆盖 A4，再检查原尺寸正文。

### 同批处理阶段对照

在旋转／翻转后的原尺寸图片上人工标出五个正文区域，保存 `rois.json`，格式为：

```json
{"center":[1000,1000,400,300],"top_left":[100,100,400,300],"top_right":[1800,100,400,300],"bottom_left":[100,2200,400,300],"bottom_right":[1800,2200,400,300]}
```

这些坐标仅演示格式，必须按自己的纸面位置重新标注；每项依次是 x、y、宽、高。移动机位后也必须重新标注。

```bash
.venv/bin/python -m lira.diagnostics.camera_quality analyze \
  --manifest /路径/sample-目录/manifest.json --rois /路径/rois.json \
  --output /home/orangepi/lira/camera-experiments
```

该命令只读样张，可在电脑上运行，不需要摄像头、服务暂停或 RKNN。输出单帧、合并、双边滤波、数字补偿、JPEG88 及 JPEG 解码图，并为每个阶段生成五区域原尺寸裁剪。只有受控抓图 manifest 可用于阶段重放；生产 JPEG 基准直接交给 OCR 比较。

### OCR 证据和正文评分

```bash
.venv/bin/python -m lira.diagnostics.ocr_compare read \
  --reference /路径/reference.txt --reference-scope body-only \
  --manifest /路径/stages-目录/manifest.json \
  --manifest /路径/baseline-目录/manifest.json \
  --stage single-000 --stage bilateral --stage digital --stage jpeg-decoded \
  --output /home/orangepi/lira/camera-experiments
```

`read` 在板上加载现有 RKNN 模型。每个样本保存真实检测／识别输入 `.npy`、检测输入预览 PNG、检测框、行裁剪、模型与源码校验值和逐项编辑计数。`--reference-scope body-only` 明确参考只覆盖正文，额外拼音、页眉、页码仍保留为插入错误，不静默过滤。若参考含全部印刷文字，用 `all-printed-text`。可选 `--expected-lines` 只能填写人工数出的物理行数。

`--rois` 可添加五区域辅助识别；辅助失败单独记录，已有效的整图评分仍保留，但整体命令返回失败以提示请求未全部完成。不同处理阶段来自同一批帧，不算独立重复。

电脑上仅评分已有识别文本，无需 RKNN：

```bash
python -m lira.diagnostics.ocr_compare score \
  --reference reference.txt --reference-scope body-only --text recognized.txt \
  --output camera-experiments
```

1. 留存现行生产采集输出，作为改善参照。生产基准由诊断隔离执行，避免修改生产采集行为。
2. 选定能辨字且不过曝的手动参数，在完整覆盖 A4 的三个距离分别采集，检查中心与四角的原尺寸文字。
3. 固定所选距离，比较从实际控制范围选出的少量曝光与增益组合。每次切换参数先丢弃过渡帧，保存连续三帧。
4. 从同一批源帧生成单帧、合并、降噪、白平衡与数字提亮、JPEG 的对照。记录合并回退、各阶段亮度和区域锐度；锐度不单独决定推荐。
5. 以相同 OCR 后端、模型、字典及参考正文评估，保存检测输入、检测框、识别裁剪和原始文字。
6. 少量候选与生产基准交替各进行三次独立采集。仅当候选三次 CER 都优于基准组中位数、完整覆盖 A4 且五区域笔画没有明显退化时，标为本场景稳定改善。

CER =（替换字符 + 删除字符 + 插入字符）/参考字符数。参考和识别两侧采用相同 Unicode 与空白规范化，保留标点。空参考正文拒绝评分，失败样本不计为零错误。

这一结果仅证明当前格式与有效负载相符，不能证明图像清晰或 OCR 已改善。它与历史的 2688 宽输出不同，后续必须按每次实际协商结果记录，不能固定套用历史尺寸。

合成平移文字夹具发现生产 `_merge_frames` 将 `phaseCorrelate` 返回的正向位移再次正向施加，扩大帧间位移。诊断保留该行为并记录位移，未修复正式算法；它是否构成当前场景主要损失仍需实测。驱动报告 Full Range，而 OpenCV NV12 转换按有限视频范围解释，报告也会保留这一转换边界。
