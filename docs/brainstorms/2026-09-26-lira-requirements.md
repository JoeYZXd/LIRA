# LIRA — 低视力智能阅读与家电助手（Low-vision Intelligent Reading & Appliance assistant）

## Summary

LIRA 是一台面向低视力老年人的桌面一体式智能设备（个人定制开发，非量产）：统一唤醒词驱动，核心能力为纸质材料 OCR 识别与语音朗读，附加能力为红外家电的语音控制。采用「本地轻量模型 + 远程大模型（OpenAI 兼容可配置端点）」混合架构，本地优先、断网核心功能可用；Phase 1 同时交付设备端软件与简易子女管理后台。

---

## Problem Frame

低视力老年人阅读纸质材料（报纸、信件、药品说明书）高度依赖他人：小字看不清、书面语看不懂，而子女不在身边时无人可求助。现有辅助手段各有短板——手机拍照识别类 App 对老人操作门槛高（触屏、步骤多）；市面阅读器功能单一且不可迭代。同时，老人家中大量传统红外家电（电视、空调、风扇）遥控器按键小、标识不清，操作困难，且高危加热设备（取暖器）存在误操作风险。

老人需要的是一个"零学习成本、放桌上就能用"的设备：说一句话就能读报纸、控家电；子女能远程帮配置、能限制危险操作。本项目为定制 Demo 项目，基于成品开发板（Orange Pi 5 / RK3588S）开发，不做外壳与量产化设计。

---

## Actors

- A1. 老人用户（低视力）：设备的直接使用者，通过语音交互（设备无触摸屏，状态反馈以语音与局域网 Web 为主），阅读纸质材料、控制家电。
- A2. 子女/管理者：通过管理后台配置家电、设置安全黑名单、开关隐私模式。
- A3. 远程大模型服务：OpenAI 兼容 API 端点（可配置，默认 GLM），负责复杂文本解读与长文本处理。

---

## Key Flows

- F1. 纸质材料阅读
  - **Trigger:** 老人唤醒设备后说出阅读指令（如"帮我读一下这个"），将纸质材料置于摄像头下。
  - **Actors:** A1，联网时含 A3。
  - **Steps:** 摄像头拍摄 → 本地 OCR 识别 → 简单文本本地 TTS 直接朗读 / 复杂文本（药品说明、长文档）经远程大模型转大白话（附带"以原说明书为准"提示）→ 语音朗读。
  - **Outcome:** 老人听到纸质材料内容的语音朗读；隐私模式开启时文本不出本地。
  - **Covered by:** R1, R2, R3, R12

- F2. 家电语音控制（含高危确认）
  - **Trigger:** 老人在设备附近说家电控制指令（如"把空调调到 26 度"）。
  - **Actors:** A1；后台配置来自 A2。
  - **Steps:** 唤醒词触发 → 意图识别判定为家电控制 → 查设备黑名单/禁用状态 → 高危加热设备则语音二次确认 → 红外发射对应码值。
  - **Outcome:** 家电执行动作；高危设备在二次确认通过或被禁用时拒绝执行并语音告知。
  - **Covered by:** R5, R6, R7, R8

- F3. 网络异常降级
  - **Trigger:** 远程大模型调用失败或网络中断。
  - **Actors:** A1。
  - **Steps:** 检测网络异常 → 自动降级为本地模式 → 朗读与红外控制继续可用，复杂文本解读功能语音告知暂不可用。
  - **Outcome:** 核心功能（OCR 朗读、家电控制）在断网状态下不中断。
  - **Covered by:** R9, R10

## Requirements

**纸质阅读辅助（核心）**
- R1. 支持摄像头拍摄纸质材料（报纸、信件、药品说明书等），本地 OCR 识别文字并语音朗读，全程无需触屏操作。
- R2. 简单指令与简单文本本地闭环处理；复杂文本（药品说明书、长文档）自动路由到远程大模型，转换为老年人易懂的大白话后朗读。
- R3. 药品说明书等医疗相关内容的解读结果必须附带"请遵医嘱、以原说明书为准"类语音提示。
- R4. 拍摄环节提供语音引导（提示对准、拍摄中反馈），适配老人操作；OCR 需处理报纸多栏排版。

**家电语音控制（附加）**
- R5. 通过语音指令控制红外家电（电视、空调、风扇），支持学习原有遥控器的红外码值（含红外接收硬件）。
- R6. 高危加热类设备（取暖器等）的开启指令必须经语音二次确认；确认逻辑在本地规则引擎实现，不依赖远程服务。
- R7. 子女可通过后台禁用指定设备，被禁用设备拒绝执行并语音告知。
- R8. 支持场景指令（如睡觉模式、回家模式），一条指令触发多设备动作。

**Agent 调度与网络韧性**
- R9. 本地能力（图像采集、OCR、语音拾音、简单意图识别、红外控制）独立于网络运行；断网时朗读与家电控制不受影响。
- R10. 联网时复杂任务自动调用远程大模型；网络异常自动熔断降级为本地模式，恢复后自动回升。
- R11. 意图隔离：阅读指令与家电控制指令严格区分，朗读文本内容不得误触发家电动作。

**隐私与安全**
- R12. 隐私模式一键开关，包含两部分：① 禁止文本上传云端（敏感材料仅本地处理）；② 关闭麦克风拾音（软件开关，局域网 Web 可操作）。
- R13. 高危设备确认、设备禁用等安全规则本地持久化，断网不失效。

**子女管理后台（Phase 1 交付）**
- R14. 提供简易管理后台：配置家电与红外码值、设置高危设备与安全黑名单、开关隐私模式、查看设备状态。
- R15. 后台与设备端通信需有基本鉴权，仅子女（A2）可访问。

**交互与基础体验**
- R16. 所有功能由统一唤醒词触发，唤醒词检测本地常驻运行。
- R17. 提供设备本地 Web 管理界面（局域网浏览器远程访问，设备不配触摸屏）：状态显示（网络/隐私模式）、设置入口、隐私模式开关。
- R18. 断网时本地 TTS 质量下降为可接受的降级方案；系统配置需降低 TF 卡写入以延长寿命。

**对话状态机与交互细节（2026-09-26 补充决议）**
- R19. ~~物料清单增加物理按键：一键切换隐私模式~~（**已取消**，2026-09-27 决议：物理隐私按键不入 BOM；隐私模式切换仅保留设备 Web UI 路径，需设备本地口令）。
- R20. 会话模型：一次唤醒 = 一条指令（指令所需的确认回合不需要再次唤醒）；任务完成或取消后回到待机，无后续跟随窗口；任何状态下说"取消/算了"结束会话。
- R21. 朗读（TTS 播放）期间：完整 ASR 关闭、唤醒词检测关闭（防自触发），仅运行白名单关键词检测，支持 {暂停、继续、停止、再读一遍、大声点、小声点}；朗读内容不进入任何意图通道（R11 由此在结构上保证）。
- R22. 朗读有状态：OCR 结果缓存，"再读一遍"不重新拍摄；长文档分块朗读，块间停顿可接收白名单命令继续。
- R23. 高危确认词表：确认集 {确认、是的、好、对、开吧}，拒绝集 {取消、不要、不对}，10 秒超时或语义不明的应答一律不执行（fail-closed）；不明应答可复述提示一次后取消。
- R24. 听不清/无法识别时：设备语音说出误解内容并给出一个示例指令引导，同一会话最多重试 2 次后礼貌回待机；绝不静默丢弃无法识别的话。
- R25. 唤醒后立即给出语音反馈（提示音+"我在听"），8 秒聆听窗口，超时复述一次提示后回待机。
- R26. OCR 失败路径：未检出文字时语音引导调整（放平、靠近），最多 2 次，仍失败则告知请家人帮忙；部分识别成功则朗读已识别内容并提示"有些地方没看清"。
- R27. 断网时拍摄复杂文本：本地朗读 OCR 原文 + 附带免责提示（不调用远程转白话），保证安全相关内容（药品说明）任何时候都可被读出。
- R28. 远程处理等待超过约 2 秒时语音反馈"正在为您仔细阅读，请稍等"，避免静默等待。
- R29. 家电指令措辞只能陈述"指令已发出"，不得暗示已确认家电真实状态；场景指令按动作逐项报告发送结果。
- R30. 后台对设备的配置变更（禁用设备、切换隐私）通过设备心跳拉取生效（在线约 60 秒内，离线则重连后生效），应用关键变更时设备语音播报。
- R31. 提供"你能做什么/帮助"语音指令，朗读简短能力清单。
- R32. 红外学习入口由子女在后台发起（学习模式），老人无需参与配对操作。

## Acceptance Examples

- AE1. **Covers R1, R9, R12.** Given 隐私模式已开启（麦克风关），when 老人说话，设备不响应任何指令；when 关闭隐私模式后拍摄药品说明书，识别与朗读正常且无任何网络请求发出（文本不上云）。
- AE2. **Covers R2, R3, R10, R27.** Given 设备联网，when 拍摄一份药品说明书，系统调用远程大模型转大白话朗读，且朗读结尾附带"以原说明书为准"提示；when 此时网络中断，设备朗读本地 OCR 原文并附带同样的免责提示（不静默、不拒读）；拍摄简单信件始终本地 OCR 朗读。
- AE3. **Covers R6, R7, R13, R23.** Given 取暖器被标记为高危设备，when 老人说"打开取暖器"，设备语音二次确认；老人说"确认"后才发射红外指令。Given 子女已在后台禁用取暖器，when 老人下达同样指令，设备拒绝并语音告知"该设备已被家人禁用"。Given 确认应答模糊（如无关内容）或超时 10 秒，when 设备不执行（fail-closed）。
- AE4. **Covers R11, R21.** Given 设备正在朗读一篇提到"打开电视"的报纸文章，when 朗读进行中，设备不执行任何家电动作（朗读期间 ASR 与唤醒词检测关闭，朗读内容不进入意图通道）；此时老人说"暂停"可暂停朗读。
- AE5. **Covers R5, R32.** Given 子女在后台发起学习模式，when 用原遥控器对准设备按下"音量+"，设备学习并保存该红外码值，此后语音指令"调大音量"可复现该动作。
- AE6. ~~**Covers R19, R12.**~~（**已取消**，随 R19 物理按键一并取消，2026-09-27 决议。）
- AE7. **Covers R30.** Given 设备离线时子女在后台禁用取暖器，when 设备重新联网拉取配置，设备应用禁用规则并语音播报"取暖器已被家人禁用"。

## Success Criteria

- 老人在无他人协助下，能通过唤醒词 + 语音完成"读报纸"和"开空调"两类任务。
- 拔掉网线后，OCR 朗读与红外家电控制功能不中断（核心韧性验证）。
- 高危设备在任何状态下（含断网）均无法被未经二次确认的指令开启。
- 设备端（Python/RKNN）+ 管理后台在 Phase 1 末可端到端演示完整流程。

---

## Scope Boundaries

- 药盒识别、物体识别、模糊文字修复、双目测距等低视力视觉辅助功能 → Phase 3（预留第二路 MIPI 摄像头接口与 NPU 算力）。
- 外壳、开模、PCB 制版、量产化设计 → 不做（个人定制 Demo 项目）。
- 家电真实状态回读（红外单向通信限制）→ 不做，设备不维护家电状态假设。

---

## Key Decisions

- 统一唤醒词触发所有功能（而非"按键阅读+免唤醒家电"双路径）：交互统一好学；代价是阅读/家电意图隔离完全依赖软件层（见 R11）。
- 远程大模型走 OpenAI 兼容可配置端点（base_url / api_key / model 均可配置，默认 GLM）：避免锁定单一供应商，便于随时切换。
- 子女管理后台纳入 Phase 1：用户明确要求，接受双线开发工作量。
- 高危设备二次确认在本地规则引擎实现：断网时高危确认反而最重要，不能依赖远程服务。
- 断网 TTS 接受质量降级：把本地算力优先留给 OCR。
- 硬件主控选型 Orange Pi 5（RK3588S, 8GB）：内置 6TOPS NPU + 多路 MIPI + ISP，兼顾当前 OCR 与后续视觉扩展；物料清单需补充红外接收头（学习遥控器必需，原清单遗漏）。
- 技术栈以 Python 为主：rknn 生态（NPU 推理）、sherpa-onnx（ASR/TTS/KWS）生态成熟，开发迭代快。
- 对话状态机规则全部采纳（2026-09-26 决议，见 R19-R32）：断网降级为朗读原文+免责、后台形态为 Web 页 + token 鉴权（设备用独立 device token）。物理隐私按键后经 2026-09-27 决议取消（R19），隐私切换仅保留设备 Web UI 路径。
- 研究结论落地的技术选型（详见计划文档）：OCR 用 PP-OCRv4 mobile（RKNN 模型仓库现成，v5 尚不可用）；语音全栈 sherpa-onnx（KWS 拼音自定义唤醒词免训练、zipformer 流式 ASR、matcha+vocos 中文 TTS）；红外用内核 gpio-ir/gpio-ir-tx + ir-ctl 原始码学习（弃用 LIRC）；空调等长帧设备按"整状态帧"学习回放。
- **取消 7 寸触摸屏**（2026-09-27 决议）：低视力场景触摸屏价值低；设备状态/设置走局域网 Web 界面（R17 改版），交互反馈以语音为主（R25 去掉屏幕反馈）。
- **取消设备配对流程**（2026-09-27 决议）：个人定制 Demo，无运行时配对 UX。device token 与 (epoch, version) 由开发期直接配置/预置（设备端配置文件写入 token；后台库重建导致 epoch 换新后，由开发者在设备端执行同步状态重置并重新拉取快照）。设备仍拒绝一切陌生 epoch 快照（回放保护不变）。

## Dependencies / Assumptions

- 硬件物料（主板、MIPI 摄像头、双麦阵列、红外收发模块、喇叭等；无触摸屏、无物理隐私按键）按预算 850~1050 元采购到位；含红外接收头。
- RK3588S 上 RKNN 部署 OCR、sherpa-onnx 中文 ASR/TTS/KWS 的可行性成立（业界成熟方案）。
- 远程大模型 API 可用且费用可承受（个人自用规模）。
- 红外学习依赖原遥控器可用；设备不校验家电真实状态（单向红外）。
- RKNN 全链路版本匹配约束：NPU 内核驱动（≥0.9.8）、板上 librknnrt 运行时、x86 转换器 rknn-toolkit2、模型仓库版本必须一致，选型镜像时锁定。
- 子女通过局域网/家庭内网访问后台（Phase 1 不做公网暴露与反向代理 TLS）。
