# 文字转语音 → 豆包实时语音静默测试

已在板子运行真实云端测试。输入为本地 Melo 合成的固定语料，转换为 16 kHz PCM，按 20 ms 音频分片与实时节奏发送到现有豆包 RealtimeSession；回复音频收集为 24 kHz WAV，不使用麦克风，不从扬声器外放。

## 结果

以下为单次实测，时间起点是最后一个输入音频分片发送完成，终点是收到首个云端回复音频包。包含云端判停、理解、工具和生成的等待；不含本地输入 TTS 预生成、连接建立和扬声器延迟。

| 输入 | 识别与工具结果 | 首包回复等待 |
|---|---|---:|
| 你好小鹿，请用一句话介绍你自己。 | 返回 LIRA 自我介绍文字及 6.236 秒回复音频；转写中出现“小小鹿”等偏差 | 1.596 秒 |
| 请告诉我设备现在的状态。 | 转写正确，调用 get_device_status，根据模拟状态生成 9.024 秒回复音频 | 2.490 秒 |
| 帮我录入声纹。 | 转写明显异常为“芒果路路生文。”，但调用 start_voice_enrollment，不能仅凭工具命中判断识别质量合格 | 2.910 秒 |
| 小鹿，我想让你记住我的声音，请帮我开始录入我的声纹。 | 转写正确，调用 start_voice_enrollment，返回 5.008 秒回复音频 | 2.318 秒 |

四次均完成云端交互。状态查询工具返回固定模拟设备状态；声纹工具仅返回模拟结果，没有进入真实录入流程，没有保存声纹或改动人物记录。

发现待改进点：模拟工具明确返回 `status=simulated`、未实际执行，模型仍说“已为你启动声纹录入”。目前确认了真实音频链路与工具选择，但不能据此认为工具执行结果的口头表达已可靠。后续需完善模型对模拟、拒绝、失败和接管状态的说明约束，并继续实测；实际保存行为仍必须由本地状态机校验。

此次使用生成语音，未验证真实麦克风、噪声、回声、儿童/老人发声、插话或扬声器播放。每组使用独立会话，不代表多轮上下文测试。

## 复用脚本

板子上运行默认三组语料：

```bash
cd /home/orangepi/lira/device
.venv/bin/python scripts/probe_doubao_text_audio.py
```

自定义文字，可重复传入 `--text`，最多十组、每组 200 字：

```bash
.venv/bin/python scripts/probe_doubao_text_audio.py --text '小鹿，请介绍一下自己。'
```

运行时读取当前服务的配置，密钥不输出。若设备正在云端对话或本地录入，会先结束该会话以避免并发；不改变所选路径，不重启服务。收到的回复不外放。工具不会真实执行。

首轮结果目录：`/home/orangepi/lira/data/doubao-text-audio-20261016-155212`。

完整声纹语句复测目录：`/home/orangepi/lira/data/doubao-text-audio-20261016-155339`。

目录中的 `results.json` 保存固定输入、转写、回复文字、工具选择与耗时，`case-N-reply.wav` 保存返回音频。自定义语料可能包含个人信息，请自行决定是否保留这些测试文件。

验证：脚本语法检查通过，四次真实云端会话完成，自定义 `--text` 路径已运行；服务保持 active/running，自动重启数为 0。没有修改生产会话客户端代码。
