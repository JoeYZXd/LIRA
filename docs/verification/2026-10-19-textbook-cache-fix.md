**Root cause**：用户确认入口为实际设备 `http://192.168.101.26:8080/dev`。设备文件与 HTTP 响应均为当前书架脚本，但旧版和新版课本 JS/CSS 共用不带内容版本的 URL，入口 HTML 也未声明缓存策略。新页面仍能运行被客户端或代理复用的旧脚本；旧脚本使用 `library-row` 输出“名称 · 页数 · 待核对”，而新脚本生成 `book-card`。已用设备部署备份中的真实旧脚本加当前模板精确复现用户提供的行格式，卡片数量为 0。未直接读取用户浏览器缓存，因此不声称确认了其具体缓存实现。

**证据**：修复前 `/dev/static/textbooks.js` 新响应 SHA256 `73048872b91f8b2e469c8580b86b9b2b5d60f4c498ef71c61fb138ff5fb69923`，包含书架实现，不含旧列表生成；旧 JS 从设备 `textbook-shelf-20261019-225047` 备份读取。旧模板引用固定资源 URL，静态响应只有 ETag，没有 Cache-Control。根因缺口位于课本模板资源引用与管理页面响应头，无法由仅使用新浏览器上下文的既有验证发现。

**Fix**：新增 `ui/static_assets.py`，按当前文件内容生成资源版本。课本模板及控制台教学资源引用自动携带内容散列版本；`/dev`、控制台登录页、`/dev/textbooks` HTML 返回 `Cache-Control: no-store`。不要求清空全部浏览器数据；重新打开或刷新入口即可获取新版资源。不更改教材数据、语音路径、鉴权方式或扩展开关。

**Prevention**：在现有书架浏览器测试中补充旧 URL 回放旧脚本的场景，修复前失败（卡片为 0），修复后通过。接口测试检查 HTML 缓存头与引用版本等于实际资源内容散列。旧资源返回也不影响新版书架。

**Confidence**：高，已复现缓存混用的完整链条并验证修复；用户具体浏览器缓存内部状态未直接检查。
