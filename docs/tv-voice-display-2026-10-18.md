# 电视语音展示接入

已部署到当前使用的豆包实时语音路径。只展示，不唤醒、不关机。

## 使用

电视先正常开机，唤醒“小鹿小鹿”后说：

- “把‘今天一起读书’用大字显示在客厅电视上。”
- 等它询问“可以把这段文字显示到客厅电视上吗？”，回答“同意显示”。
- 图片可说“把登记的测试图片显示到客厅电视上”，等询问后回答“同意显示”。
- 不想展示时说“不要”“不用了”或“取消显示”。

即使最初的请求已提到显示，也仍会再询问一次。只有下一轮对本次询问的明确
同意有效。图片工具只使用本地登记的 PNG/JPEG，不生成新图片、不访问任意 URL。
当前板上登记了 `lira-demo.png` 测试色卡。后续生成图片需要先保存到登记目录。

## 通用 function calling 与课本练习

会话模型通过 `prepare_tv_display` 准备投屏，参数是 `content_type`（text/image）、
`text`、`image_id` 和可选 `caption`。参数可以不完整：工具返回 `needs_input`、
`missing_parameters` 和 `question`，模型结合对话追问，补齐后重新调用。
参数收集完成与展示许可是两个步骤；仍必须下一轮明确同意才能真正显示。
原有 `prepare_tv_text/image` 保留为内部兼容调用，不再向模型暴露两个竞争入口。

首个场景是**看汉字，在纸上写拼音**，字表来自已核对的教材。PDF/图片导入、OCR 和核对界面见文末增量；自动批改与朗读默写尚未实现。

模型先用 `list_practice_textbooks` 查教材目录，再用 `prepare_pinyin_practice`：

| 参数 | 含义 |
|---|---|
| `book_id` | 教材编号；只有一本时可以省略，多本必须确认 |
| `scope_type` | `lesson` 单课、`unit` 单元、`lesson_range` 连续课文 |
| `start` | 课号、单元号或起始课号 |
| `end` | 连续课文的结束课号，包含该课；单课/单元不使用 |
| `character_group` | `four` 四会字、`two` 二会字、`all` 两类都练 |

例如：“帮我练第 3 课”“今天默第 2 单元”“练第 3 课到第 5 课”。
缺少范围、教材或字类时通过对话补齐。四会字按本家庭约定要求会读、会写、会拼音、
会说；二会字要求会读、会拼音。两种类别不代替本次作业的具体练习范围。
本地还核对真实转写中是否出现了与参数一致的字类选择，防止模型自行填入默认类别。
含糊/否定表达可能需要再明确说一次“四会字”“二会字”或“两类字都练”。

工具从教材字表取字，按课号及教材字表顺序合并，重复字保留第一次，每行四字，
复用通用投屏准备与许可流程。确认问题会明确教材、范围和字类。
屏幕不显示拼音答案；字数较多时沿用接收应用的上下滚动。没有教材、范围不完整、
字表缺失时均不猜字、不展示。未实现逐字自动翻页。

### 教材导入的数据约定

`LIRA_TEXTBOOK_DIR` 指向本机已核对教材的目录；每个 `.json` 文件一本教材：

```json
{
  "id": "chinese-grade1-term1",
  "title": "教材版本·一年级上册",
  "lessons": [
    {"number": 1, "unit": 1, "title": "课文标题", "four": ["日", "月"], "two": ["山"]}
  ]
}
```

此示例仅说明格式，不是实际课本内容。`number` 是同一单元内唯一的课号，`unit`
是单元号；`four/two` 均必须存在，每项为一个汉字，空数组表示已核对确实无此类字。
未核对的数据不能用空数组代替。文件最多 1 MiB，读取前 64 本，每本最多 200 课。
无效 JSON、重复教材 ID、同单元重复课号、非汉字字表和符号链接不成为可用教材。
导入入口在保存前要求逐课核对，并遵守此数据约定。

## 初次接入实现

- 六个工具：`list_tv_images`、`prepare_tv_text`、`prepare_tv_image`、
  `confirm_tv_display`、`cancel_tv_display`、`get_tv_display_status`。
- 准备时固定文字或图片字节，创建一次性 request_id；90 秒后失效。
- 本地监听助手询问完成与随后真实 ASR 转写；模型不能传入 `approved=true`
  绕过许可。拒绝、含糊回答、内容替换、询问被打断均不发送。
- 发送为独立异步任务，语音接收不中断。退出会话、切换路径、隐私模式或明确
  撤回会取消未完成发送。已经到达电视的指令不能撤回；不因此发送关机或返回按键。
- 有效请求先查询 40100；必要时调用小米 6095 的 startapp 拉起接收应用。
  不包含电源接口。屏幕明确关闭时失败，不尝试唤醒。
- POST 成功仅为接受；必须读到相同 rendered_id 且 foreground=true 才返回 displayed。
  提交后不再次拉起界面，避免用户按返回后又被抢回。
- 本地图片读取和目录扫描离开语音事件循环；目录列表最多 64 项，单图最多 2 MiB。
- 问电视展示许可时暂停主动身份询问，避免“同意”被另一道问题混淆。
- 现有后台语音实验室仍模拟业务工具，不会通过实验室误操作电视。

## 课本导入（2026-10-18 增量）

新增 `/dev/textbooks`（沿用开发控制台登录）及 `/dev/api/textbooks` 接口。支持 PDF、PNG、JPEG 合计 100 MiB / 最多 200 页，先生成独立草稿，设备 OCR 后将文字交给独立模型请求整理。该请求不联网搜索，不使用家庭会话记忆。用户可对照原页修正单元、课号、标题、四会字、二会字及来源页；逐课勾选核对并明确确认后才原子写入语音教材库。

草稿目录默认与 `LIRA_TEXTBOOK_DIR` 同级的 `textbook-imports`，可用 `LIRA_TEXTBOOK_IMPORT_DIR` 覆盖。草稿识别不会直接发布；识别失败和服务重启保留已提取文字，支持重试。阅读与识字课在不同单元重复课号合法，语音查询存在歧义时追问单元。

设备依赖新增 Pillow / pypdfium2（`textbooks` 可选依赖组）。部署备份为 `/home/orangepi/lira/deploy-backups/textbook-import-20261018-203643`，按 manifest 恢复已有文件，仅移除 manifest 标记为此前不存在的文件后重启服务即可回退。保留教材与草稿，不回滚家庭数据库。本轮未操作电视、唤醒或关机。
