# ce-brainstorm HTML 脑图协作

这是 ce-brainstorm 的展示与反馈层。ce-brainstorm 负责问题探索、取舍、需求与结论；本 skill 负责把这些内容呈现为可持续交互的 HTML 脑图。仅依赖已安装的 `compound-engineering:ce-brainstorm`（或环境中同等的 `ce-brainstorm`）；从当前技能目录发现并读取它，不绑定插件版本或绝对路径。缺少该技能时说明缺失，不伪装成已执行。

本文件为完整、可单独分享的指令型 skill；不依赖某个项目的脚本、页面、端口或用户路径。生成页面或保存服务时，在目标环境按下述契约创建或复用所需代码。

## 先判断调用来源，防止脑图套脑图

先解析本次请求及经读取验证的请求记录，再决定是否渲染。

| 情形 | 处理 |
| --- | --- |
| 普通用户发起 ce-brainstorm | 正常运行 ce-brainstorm，以同名 HTML 交互脑图和完整 Markdown 正文承载讨论。 |
| 用户继续已有脑图 | 更新原有 HTML/Markdown 同名文件对，保留路径、稳定节点编号与已有结论。 |
| `brainstorm_origin: existing-mindmap`，或已验证请求记录的 `kind: idea` 指向既有 HTML 与节点 | **仅使用 ce-brainstorm 对该节点发散**。不重新加载此展示流程，不生成第二张脑图、iframe 或子脑图。 |
| 用户明确说“在这张脑图的某节点 brainstorm/idea” | 与上一行相同；不能因为没有机器标记就重新造图。 |
| 脑图请求为 `modify` / `discuss` | 按下文分别执行或讨论；修改不自动升级为脑暴。 |
| 用户明确要求纯文字/Markdown，或上游自动流水线强制 Markdown | 尊重该格式；不额外创建 HTML。 |

已有脑图中的 idea：在当前聊天给出与原节点有关的想法、差异和取舍。ce-brainstorm 可正常提问，但不因其默认落盘流程新建脑图。用户要求将候选想法写入原节点时，标注为建议；未经选择的想法不能覆盖已确认结论。讨论形成结论后，再更新原节点并高亮。

不要把“脑图协作方式”“如何提交反馈”“技能安装”等工具流程变成被讨论产品的功能分支。它们属于工具栏、侧栏、帮助或独立技能说明。

## 普通脑暴的输出

遵循 ce-brainstorm 的探索、证据、对话节奏和产物契约，不以制作页面替代真正的脑暴。讨论中的草案明确标为草案；未解决的问题不能被标成已确认或可实施。

- 默认同时交付同名 `.html` 与 `.md`：HTML 为交互版，Markdown 为完整文本正文；已有文件对原位同步。用户明确要求双格式时，以此偏好覆盖 ce-brainstorm/ce-plan 默认的输出互斥规则，不修改插件缓存。
- 遵守 ce-brainstorm 对产物目录、文件命名、元数据及需求标识的规则。尚在讨论时保留未决项；不声称规划已完成。
- 产物是可直接由浏览器打开的单个 HTML，CSS/JS 内联，不依赖 CDN、插件或联网字体。`details/summary`、DOM/SVG 即可；没有必要强制 canvas、3D 或前端构建链。
- 需求和结论保留可读取的 DOM 文本、稳定锚点与来源依据，不能只画在 canvas 中。
- 默认只显示根节点和主分支，细节折叠；由用户自行展开。提供恢复概览、全部展开、搜索、缩放和滚动浏览。
- 节点使用稳定、可在聊天引用的编号。更新后不重排旧编号，不因删除节点而重新编号。
- 采用适合当前项目的视觉风格；没有既有方向时，可用温暖清晰的浅底、圆润卡片与克制阴影。

### UI 相关节点的小示例

在节点展开后的文字描述旁加小型效果草图，不把示例挤成独立大页面。

- 配色显示色块和名称；圆角/阴影显示小卡片；动效提供可点体验；进度、状态、日志、布局用小样展示。
- 示例和文字同属一个节点；窄屏允许小样移到文字下方。
- 波形、模型回复、人数和耗时等演示值必须标成示例，不能冒充真实设备或模型状态。
- 动效由用户触发，支持 reduced-motion；没有实际功能的示例不显示假成功。
- 需要时应用目标环境已安装的 UI/UX 技能；不把某项目的配色或框架强制推广到所有脑图。

### 每轮变化

维护修订号、本轮摘要及简短历史。对本轮新增/修改的内容节点高亮，并显示文字标记；折叠祖先显示内部更新数。“下一处更新”自动展开祖先、定位并聚焦。

新一轮的高亮替换上一轮高亮，不因用户查看过就清除。仅删除内容时在本轮摘要列出被删除的节点；没有可定位更新时按钮应禁用或给出提示。工具外观变化不应把所有产品节点标成需求变化。

## HTML 与 Markdown 同步契约

- **同一内容，两种用途。** Markdown 是可审阅、版本管理和后续规划/实施使用的完整正文；HTML 是交互视图。不是把 HTML 链接或内容摘要当作 Markdown 版。
- 两份文件使用同一目录和 basename，保留相同标题、稳定节点/R/F/AE/U/KTD 编号、修订号、更新时间及 readiness；互相标明对应文件。Markdown 用 frontmatter，HTML 用可见元数据，不把 Markdown frontmatter 粘进 HTML。
- Markdown 包含目标、全部当前脑图节点的有效描述/确认状态/未决项，以及已生成的完整产品合同、技术方案、开发单元、测试场景、验证与完成条件。原始尚未处理的输入仍留在 requests 文件，不混入确定正文。
- HTML 中的配色/圆角/动效小样可在 Markdown 中用文字、色值、图注或静态图表达；控件、动画、浏览器草稿和本地保存服务不必复制成 Markdown，也不能变成产品需求。
- 用户修改 HTML 节点时，先核对当前两份内容，按稳定编号把已批准变化合入 Markdown，再同步 HTML；不能用旧 Markdown 覆盖新 HTML。Markdown 有外部修改时同样核对，冲突涉及含义就先解决冲突，不能静默选一份覆盖另一份。
- `modify` 执行后两份同步；`discuss` 未结论时两份最终正文均不变；`idea` 仅发散，不另建文件对，选定或明确作为建议保存的结果回到原文件对。
- 用 ce-plan 从脑图制定开发计划时，继续丰富原文件对，不丢弃交互 HTML，也不能只补 HTML 而漏掉 Markdown。先核对两份再决定 readiness，不能因“同名另一扩展名”就把仍同步维护的 HTML 误判成过期产物。
- 保存前准备好两份内容，分别以原子替换保存；两份都成功且语义核对后才声明同步完成。中途失败保留可恢复内容并报告哪份未同步，不伪称两文件写入是跨文件原子事务。
- 每轮核对节点/需求/开发单元编号集合、完整描述、决策状态、未决项、依赖和验证内容相同。Markdown 不含表单脚本、示例回复充当真实结论或未展开而漏掉的节点。
- 修订摘要在两份保留；HTML 高亮本轮内容变化，Markdown 可用修订摘要/节点备注表达，不需要模仿交互高亮。只改工具或输出格式时不要把产品需求标成已修改。
- 用户明确指定单格式、禁止生成某文件或流水线硬性约束时尊重例外，说明哪一份没有生成。后续回到普通交互工作流时，补齐缺失格式再继续维护。

## 节点反馈入口

每个节点标题右侧的“用户要求 / 建议 / 已确认”等状态标签旁，放一个小钢笔 SVG icon。不要显示“修改/讨论/idea”文字，不独占一行。图标需有可访问名称、键盘焦点和 title。点击图标打开操作对话框，不能误触节点展开/折叠。

对话框包含节点编号/标题、当前描述、三个选项、输入框、保存反馈和关闭入口：

| kind | 含义 | 聊天收到通知后如何处理 |
| --- | --- | --- |
| `modify` | 用户输入直接修改要求 | 直接按要求更新对应节点，不主动发起讨论。仅在要求冲突或无法执行时说明具体问题。 |
| `discuss` | 用户输入意见/疑问 | 先反馈判断，与用户交流；得到结论后再更新脑图。保存意见不等于结论改变。 |
| `idea` | 用户输入希望发散的方向 | 设置既有脑图来源标记，只使用 ce-brainstorm 发散；按前述防嵌套规则处理。 |

按节点和操作类型暂存输入草稿。关闭、切换模式、保存失败时保留输入；成功落盘后清除已提交草稿，防止重复恢复。提交中防止重复点击、模式变更及内容错配。

## 本地落盘与通知

优先复用目标环境可用的本地保存能力。普通 `file://` 页面不能凭空获得任意路径写权限：若需要保存服务，可在目标项目生成小型 loopback 服务与启动器，或使用由用户选择目标的浏览器文件 API。服务脚本是页面运行支持，不是产品需求，也不假定本 skill 附带了运行时。

- 未提交草稿可放 localStorage；成功提交的请求必须真实写入本地文件，不能把 localStorage 说成模型可读取的磁盘文件。
- 请求文件建议与 HTML 同名，扩展名为 `.requests.json`。记录 schema、文档路径和 requests 列表；每条含唯一 id、节点编号、kind、用户原文、带时区的 created_at、处理状态。
- 使用原子写入，保留已有记录；重试使用同一个请求 ID，保证幂等。文件损坏时保留原文件并报错，不用空队列覆盖。不同请求或处理状态更新不能丢失期间新增的记录。
- 输入仅按文本展示，不执行 HTML/脚本。保存服务只绑定回环地址，限制可写文件、请求大小与操作类型，并采用本地能力 token 与来源校验。
- 首次失败就提供可恢复反馈，保留输入；不能在失败或超时时显示“已保存”。不以无限重试维持假进度。
- 显示待处理列表和节点待处理标记。待处理标记与本轮内容高亮分开；刷新重新读取真实记录。

状态约定：`pending_modify`、`pending_discussion`、`pending_brainstorm`。修改完成、或讨论结论已更新脑图后改为 `applied`；idea 已在聊天呈现后可改为 `ideas_presented`。保留原文与 id，添加简短 result 和 resolved_at；用户未形成讨论结论时继续保留待讨论状态。

提供“保存并复制通知”和“复制全部待处理通知”。如果环境确有向当前聊天发消息的工具，并且用户已授权，可以调用；否则复制通知并明确请用户粘贴到当前聊天。不得凭空声明已经发消息、已经调用模型或后台脑暴完成。复制失败时展示可手动选择的通知文本。

idea 通知必须携带以下防递归上下文；modify/discuss 不因此调用脑暴：

```text
脑图有更新，请读取本地请求记录并按类型处理。
brainstorm_origin: existing-mindmap
mindmap_path: <现有 HTML 的路径>
node_id: <节点编号>
request_id: <请求 ID>
request_file: <本地请求文件路径>
kind: idea
对本节点仅使用 ce-brainstorm 发散，不生成新的脑图；需要落盘的内容同步更新原 HTML/Markdown 文件对。
```

多个请求混合交接时，注明来源为既有脑图，并逐条携带 id、node_id、kind；防嵌套标记不改变 modify/discuss 的语义。读取记录核对节点与原文后再处理，不仅凭通知摘要改内容。

## 检查与交付

验证默认折叠、节点操作不触发展开、搜索/更新定位、UI 示例、桌面/小屏与键盘操作。存在持久化服务时验证实际落盘、刷新恢复、三种状态、重试幂等、错误保留草稿及文本转义。没有浏览器验证能力时如实说明已检查的范围。

给用户可点击的 HTML 与 Markdown 绝对路径；HTML 也可提供已启动的 loopback URL。需要服务时交付启动方法，若页面提供 Markdown 链接，核对 file:// 和服务路径下都可访问。不能把仅有 JSON、摘要 Markdown 或尚未启动的 URL 当作完整交付。

## 全局关联（安装时按用户授权写入一次）

把本文件保存为用户级技能目录下的 `ce-brainstorm-mindmap/SKILL.md`。全局 `AGENTS.md` 只需加入下面的路由规则；路径使用实际安装位置。不要修改插件缓存里的 ce-brainstorm，也不要每次运行重写全局配置。

```markdown
## ce-brainstorm 的脑图展示

- 普通 ce-brainstorm 会话默认同时使用 ce-brainstorm-mindmap；从当前技能目录发现并读取它的 SKILL.md。生成同名 HTML 交互版和完整 Markdown 正文，后续 ce-plan 继续同步维护该文件对。
- 若来源为已生成脑图的节点 idea（brainstorm_origin: existing-mindmap、经核对的 kind: idea 请求，或用户明确在既有节点发散），只运行 ce-brainstorm，不运行脑图生成流程，不新建/嵌套脑图；需要保存的结果同步回写原 HTML/Markdown 文件对。
- 既有脑图的 modify 直接执行，discuss 先在聊天讨论后更新，不因此开启另一场脑图生成。
- 脑图工具的协作流程不得混入正在讨论的产品功能。用户显式格式要求和上游流水线格式约束优先。
```
