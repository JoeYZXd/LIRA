# LIRA 家庭助手首页改版与文字聊天（对话先行，档案与控制分批跟进）

## Summary

把设备面板 `/` 从运维风"设备面板"改版为温馨的家庭小助手主页（聊天入口 + 常用功能快捷化 + 调试信息收纳），并新增按人识别的文字聊天通道；本次实施第一批（改版 + 选人 + 纯对话），按人档案双通道注入为第二批、聊天控家电与首页快捷操作为第三批，本档一并锁定其产品决策。

---

## Problem Frame

设备面板 `/`（8080）目前是纯工具定位：状态卡、隐私开关、音量/语速表单、家电只读表、开发者控制台链接平铺一屏。这是 U7 交付时"设备维护面"的形态——对开发者顺手，对家人没有"这是我家的助手"的使用感：常用操作（调音量、开关隐私）和运维信息混在一起，没有任何一个"回家打开它"的理由。

同时，助手只有语音一条交互通道，而语音会话模型刻意"一唤醒一指令、无跟随窗口"（R20），远程 LLM 人设也明确"不主动续聊"（`VOICE_ASSISTANT_SYSTEM_PROMPT`）。这个设计保证了指令通道的干净，但代价是：多轮的、连续的交流没有容器——LLM 对这个家庭的具体成员零了解。对固定老人，回复无法随着解加深变得贴切；对孩子，教学辅助（按年龄、教育背景适配）无从谈起；"大模型在某个功能领域的应对经验"没有任何沉淀机制。

两面是同一枚硬币：家庭缺一个"入口"（页面），助手缺一个"了解人"的通道（文字对话），两者天然长在一起。

---

## Actors

- A1. 老人用户（低视力）：主通道仍是语音；是档案个性化的核心受益者（批次二）；一般不直接打字操作页面。
- A2. 子女/家人：页面主要使用者——改设置、与助手文字聊天、维护家庭成员身份、（批次二）查看修正档案。
- A3. 孩子：文字聊天使用者之一；（批次二）教学档案（年龄/年级/薄弱点）生效后的核心受益者。
- A4. 远程大模型服务：聊天的对话执行者与（批次二）档案提炼执行者。
- A5. 开发者：调试信息收纳后仍从次级入口使用开发者控制台。

---

## Key Flows

- F1. 选人进入聊天并多轮对话（批次一）
  - **Trigger:** 家人在首页点聊天入口
  - **Actors:** A2 或 A3，A4
  - **Steps:** 选人（预置家庭成员身份）→ 进入会话 → 发送消息 → 助手以"小丽拉"人设回复 → 可连续追问 → 退出后历史按人保留
  - **Outcome:** 家庭成员从局域网浏览器与助手完成多轮文字对话；历史可在下次进入时翻看
  - **Covered by:** R5, R6, R7

- F2. 隐私模式下的聊天降级（批次一）
  - **Trigger:** 隐私模式 ON 时发送聊天消息
  - **Actors:** A2/A3，A4
  - **Steps:** 消息提交 → 联锁检查 → 不发起远程 LLM 调用 → 本地 LLM 可用则本地应答，否则明确提示暂不可用
  - **Outcome:** 聊天内容不出设备；不静默失败
  - **Covered by:** R8, R10

- F3. 档案自动提炼与双通道注入（批次二）
  - **Trigger:** 聊天/语音对话产生可沉淀的成员信息
  - **Actors:** A1, A2, A3, A4
  - **Steps:** 对话发生 → LLM 提炼更新该成员结构化档案 → 家人可查看修正 → 后续文字与语音对话均注入该档案
  - **Outcome:** 助手按人个性化：对老人回复贴其需求，对孩子按年龄/教育背景辅导；档案错误可被家人纠正
  - **Covered by:** R11, R12, R13

- F4. 聊天控家电（批次三）
  - **Trigger:** 聊天中出现家电指令（如"把空调调到 26 度"）
  - **Actors:** A2/A3；高危规则来源同语音（后台配置）
  - **Steps:** 意图识别（复用语音路由）→ 高危设备在聊天内二次确认 → 执行 → 回复遵循措辞纪律（只说"指令已发出"）
  - **Outcome:** 文字通道获得与语音同权、同安全规则的设备控制；模糊/拒绝/超时不执行（fail-closed）
  - **Covered by:** R14

## Requirements

**首页改版（批次一）**
- R1. `/` 首页改版为温馨家庭小助手风格：问候、聊天入口、常用功能为主视觉；大字号高对比度，适配手机/平板/电脑浏览器；设计过程使用 ui-ux-pro-max 设计能力产出，并经截图对照验证
- R2. 音量/语速改为顺手快捷控件（滑条或步进按钮），保存路径不劣于现状
- R3. 调试与运维信息（状态卡、家电只读表、开发者控制台链接）从首屏移入折叠区或次级入口，首页默认不展示但仍可达
- R4. 现有能力行为等价不回退：隐私开关（含口令校验与 fail-closed 引导）、口令设置页、`/status` 只读 JSON 语义保持不变

**文字聊天（批次一）**
- R5. 聊天入口进入先选人：预置家庭成员身份（名字/头像）；成员的增改由家人在页面上完成；身份与成员数据为设备本地数据
- R6. 多轮对话：同一会话内上下文连续；复用远程 LLM 链路，助手人设与语音端同源（"小丽拉"）；人格一致、文字端可不简短
- R7. 聊天历史按人保存于设备本地，本人可在聊天页翻看；不同步到子女管理后台、不写入项目日志（内容纪律延续）；隐私 ON 不阻止本地历史保存（用户主动输入的内容），只拦截远程上传
- R8. 隐私联动：隐私 ON 时聊天不发远程 LLM；本地 LLM 未配置或不可用时明确告知"暂不可用"，不静默失败
- R9. 聊天不改变安全状态：入口无需口令；批次一聊天为纯对话，不触发家电、不影响隐私状态
- R10. 聊天的请求/响应仅以事件与耗时形式进日志（来源标记 web-chat），内容不落日志

**按人档案与经验注入（批次二，本次不实施）**
- R11. 每人一份结构化档案（老人：需求/习惯/注意事项；孩子：年龄/年级/教育背景/兴趣/薄弱点），由 LLM 在对话后自动提炼更新，家人可查看与修正
- R12. 档案注入双通道：文字聊天与语音对话的 LLM 上下文都包含当前说话人的档案，使语音端同样"更懂 TA"
- R13. 档案提炼受隐私联动：隐私 ON 时提炼更新停止（对话本身按 R8 降级）

**设备控制融入页面（批次三，本次不实施）**
- R14. 聊天可控家电：复用语音意图路由与全部安全规则（高危设备聊天内二次确认、fail-closed、措辞纪律——只说"指令已发出"不暗示真实状态）
- R15. 首页家电快捷开关：点按即执行，高危设备页面上二次确认
- R16. 一键阅读入口：触发与语音等效的阅读流程（拍摄→OCR→朗读），页面可查看最近一次朗读文本（展示纪律同 R7：只在请求/响应与页面出现）

## Acceptance Examples

- AE1. **Covers R1, R3.** Given 打开 8080 首页，when 页面加载完成，then 首屏为问候/聊天入口/常用功能，无状态卡、家电表与开发者链接；这些信息经折叠区或次级入口仍可达。
- AE2. **Covers R5.** Given 首次进入聊天页，when 选择成员"妈妈"，then 以该身份进入会话，后续历史归入该成员名下。
- AE3. **Covers R6.** Given 会话中刚讨论过某话题，when 追问"你刚才说的第二个是什么意思"，then 回复利用本轮上下文而非当作全新问题。
- AE4. **Covers R7, R10.** Given 成员 A 有一段历史聊天，when 其再次进入聊天页，then 可翻看自己的历史；同时项目日志与子女后台中均不存在聊天内容。
- AE5. **Covers R8.** Given 隐私模式 ON 且本地 LLM 未配置，when 发送聊天消息，then 收到明确的"暂不可用"提示，且无任何远程请求发出。
- AE6. **Covers R4.** Given 改版后的页面，when 执行隐私开关（口令校验、未设口令引导）、音量/语速调整，then 行为与改版前等价。
- AE7. **Covers R11, R12.** （批次二）Given 聊天中老人多次提到"读报声音要慢"，when 对话结束档案更新，then 其后语音对话的回复语速与措辞体现该偏好，且家人在页面能看到这条档案并可删除。
- AE8. **Covers R14.** （批次三）Given 聊天中说"打开取暖器"（高危），when 助手二次确认而用户回复无关内容或超时，then 不执行并明确告知；确认后才执行且回复只称"指令已发出"。
- AE9. **Covers R15.** （批次三）Given 首页有取暖器快捷开关（高危），when 家人点按，then 页面弹出二次确认，确认后执行；被后台禁用的设备点按后提示"已被家人禁用"。

## Success Criteria

- 批次一交付后：家人在局域网浏览器打开设备页面，无需说明即可找到聊天入口、以自己身份与小丽拉多轮对话；页面呈现家庭助手气质，调试信息不再首屏。
- 现有能力零回退：隐私开关、口令流程、音量/语速、`/status` 行为等价（AE6 进入回归）。
- 隐私降级可验证：隐私 ON 期间事件日志中无远程 LLM 调用记录（AE5 成为回归项）。
- 设计质量：改版在手机/平板宽度断点下经截图对照验证，无明显布局破损。
- 交接质量：批次二/三启动时，本档已锁定的决策（档案机制、双通道、安全规则复用、隐私语义）可直接续用，无需重新澄清产品行为。

## Scope Boundaries

- 第二、三批内容本次不实施：按人档案与双通道注入（R11-R13）、聊天控家电与首页家电快捷开关、一键阅读（R14-R16）
- 公网/外网访问聊天：维持 Phase 1 局域网边界（远程场景走 VPN 回家）
- 聊天的语音输入：本期纯键盘输入，浏览器语音识别不做
- 聊天记录云备份/多设备漫游：不做，内容数据只在设备本地
- 老人在页面上的管理操作：成员/档案维护由家人负责，页面不为老人增加管理负担
- 助手主动发起对话/推送：本期聊天仅为用户发起

## Key Decisions

- **并入现有设备 UI（8080）而非新服务**：沿用 2026-10-03 开发者控制台的同款决策——复用装配、鉴权与部署形态，零新增攻击面。
- **聊天复用远程 LLM 链路与"小丽拉"人设**：文字与语音是同一个助手的不同入口，人格一致；不另起对话栈。
- **进页选人作为身份来源**：最简单可靠的认人方式；接受"选错人"的可能（家庭场景可容忍），不做人脸/声纹识别。
- **结构化档案而非原始历史注入**：字段可控、家人可查看修正、token 成本小；聊天历史仅作数据底座与翻看，不直接进 prompt。
- **双通道注入**：老人主通道是语音，只注入文字通道则档案价值落空；代价是语音端说话人认定问题（见 Outstanding Questions）。
- **聊天能控家电但后置批次三**：安全规则必须全量复用（高危确认/fail-closed/措辞纪律），第一批先收敛在纯对话，把安全面增量留到架构验证后。
- **隐私同规则降级，主动打字不设例外**：保住 R12"禁止文本上云"的字面承诺与家人对隐私开关的信任模型。
- **聊天内容设备本地持久化、不落日志、不同步后台**：延续内容纪律；历史既是功能（翻看）也是批次二档案的数据底座。
- **UI-UX-PRO-max 用于实现期设计**：设计智能（风格/配色/字体/布局）在实现阶段以该能力产出，本档只约束设计目标（温馨、大字号、快捷、调试隐藏）。

---

## Dependencies / Assumptions

- 远程 LLM 端点可用且费用可承受（既有前提）；本地 LLM 当前为可注入接口（可为 None），聊天降级路径的实际可用性取决于其配置。
- 页面维持"服务端渲染、无前端构建链"的既有纪律；聊天页的交互形态（刷新/轮询/长连接）由规划决定，若突破该纪律属规划层显式决策。
- 设备无触摸屏（2026-09-27 决议维持），页面面向家庭局域网内的手机/平板/电脑浏览器。
- 家庭成员身份为设备本地新增数据类，与家电库同级的本地库管理（具体存储随规划定）。
