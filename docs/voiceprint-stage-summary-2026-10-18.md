# LIRA 声纹识别阶段总结

日期：2026 年 10 月 18 日。范围：声纹录入、自然聊天中的本地身份识别、豆包实时语音上下文、用户反馈与聊天归属。

本阶段暂停继续开发和调参，保留已部署版本。声纹功能已具备录入、测试、自然聊天查档、候选询问、反馈记录和身份上下文传递的完整代码链路，但真人自然聊天中的稳定识别和全部反馈闭环尚未完成验收。不能将自动测试通过、一次高分或云端接口回执视为识别准确率已经达标。

当前没有启用自动调整阈值、自动训练模型或自动更新声纹模板。已经积累的匹配过程和用户标签，是后续 tuning 的数据基础，不代表系统正在自我学习。

## 一 当前方案与职责

豆包模式直接上传语音，由豆包完成转写与对话；本地从生产收音流保留短时音频、提取声纹并查本地档案。声纹模型负责声音相似度，豆包负责对话和弱连续性辅助，固定程序负责状态、采集、保存、反馈校验和归属管理。

| 角色 | 当前职责 | 不作为其判断依据的事项 |
| --- | --- | --- |
| 豆包实时语音 | 听说交互，通过 function calling 使用本地能力；可报告上下文是否像同一人 | 不直接比对本地声纹，不凭话题、自报姓名或模型猜测认证身份 |
| 本地声纹模型 | 从合格音频提取向量，计算档案匹配及声音连续性分数 | 不理解对话内容，不负责确定聊天记忆归属 |
| 本地固定程序 | 控制采集生命周期、查档预算、候选确认、反馈落库、身份保持与变更 | 不将一句短语低分直接等同于换人，不将口头确认说成声纹验证通过 |
| 云端语音播报及本地播放器 | 生成、播放回答和候选问题；本地处理播放占用、尾音及打断 | 文字已生成或音频已返回，不等同于整句已经物理播放完成 |
| Typesafe Jev | 保留为其他交互路径的可选能力 | 当前豆包声纹链路不依赖 Jev 决策或本地 ASR 切换 |

身份来源区分为 `voiceprint`、`user_confirmed`、`user_corrected`。后两种是用户口头确认或纠正，不是模型声纹匹配成功。

身份状态和聊天归属分开维护：会话中确认了某个成员，不会自动把整场聊天或旧聊天绑定给该成员。个人记忆的聊天归属仍由后台选择具体轮次后明确关联。

## 二 已实现的功能与规则

### 录入和档案管理

- 豆包语音录入通过 function calling 调用本地采集、检查、保存、取消，全程继续豆包交互，不为录入临时切换本地 ASR。
- 后台声纹档案页支持引导式添加、改名、明确选择替换、重新录制、删除声纹和一句话测试。
- 引导录入使用四段不同的日常口语文案，每段至少八秒有效语音。要求自然语速、平常音量和日常使用距离，不要求刻意喊叫、耳语或制造快慢变化。
- 后续采集段与此前综合模板比较，临界段先保留；四段组成模板后，再读独立文案验证。验证段不参与模板，避免自己验证自己。
- 替换按用户明确选择执行，保留成员 ID 及已有记忆；删除声纹不等于删除成员或聊天。普通关闭和同标签页刷新保留未过期进度，服务重启和录入总时限仍会使未保存进度失效。

### 识别和身份保持

| 规则 | 当前数值或行为 | 含义 |
| --- | --- | --- |
| 初次自动认人门槛 | 0.80 | 还需满足分差和输入一致性检查，不是“80% 身份概率” |
| 最高与次高分差 | 0.10 | 防止两个档案过于接近时直接采用最高名次 |
| 候选下限 | 0.50 | 只用于提出未确认候选，即使只有一人超过也不自动认人 |
| 引导录入段比较 | 0.85 为普通段；0.73 至 0.85 为临界段 | 属于采集一致性规则，不能替代日常认人门槛 |
| 无候选时查档 | 2、5、10 秒里程碑，最多三次 | 每次使用合格声音推进有界累计；足量仍不匹配后停止反复查库 |
| 原音查询窗口 | 最多保留十秒 | 多段查档拼接原音重新提取，不以平均向量替代原音查询 |
| 连续性统计 | 最近六窗，按有效时长加权，每窗权重一至五秒 | 用于身份保持和声音变化核对，不是对身份置信概率做平均 |

已确认身份遇到单句波动继续保留。实际换人需要连续多段、足够时长、加权分数和原音重新提取共同支持；豆包的 `same_person` 或 `person_changed` 只能辅助，不能单独认定换人或强制合并声音。具体时长及核对条件保留在实现和专项文档中，没有在本次暂停时统一降低门槛。

找到候选后，本地在正常回答结束、扬声器和尾音释放并出现空隙时，使用豆包官方 `speech_text_buffer.commit` 插话合成询问。问题未完成不接受确认，明确反馈通过校验后保存。被打断后的重试及拒绝打扰处理仍有缺口，见待办。

## 三 开发中遇到的问题及处理

| 问题 | 原因和解决方案 | 当前结论 |
| --- | --- | --- |
| 模型说要录制，却没有执行下一步 | 自然语言承诺没有对应本地动作。改为工具驱动采集、检查、保存、取消，并以本地返回结果为准 | 已实现、部署；不能只看模型口头回答判成功 |
| 豆包交互中录入又切换本地 ASR | 对话路径与录入路径混用。豆包模式保持同一实时会话，本地仅执行录入能力 | 已修复 |
| 第三段录入反复不通过，看起来卡住 | 逐段比较过严；错误提示还会被轮询旧状态覆盖。改为此前综合模板比较、临界段保留、最后独立验证，并持续展示拒绝原因 | 已修复流程；不据此保证所有人的识别效果 |
| 确认替换后未保存，关闭又丢进度 | 前端“应用修改”和“保存”分两步，关闭却执行取消。改为验证通过后一次确认保存，成功以 `saved` 为准；关闭保留进度，放弃需明确操作 | 已修复；重启和超时仍会丢失未保存的内存进度 |
| 有档案却自然聊天匹配不上 | 增加最高分、次高分、阈值、分差、拒绝原因及模型和音频质量信息，先建立可核对证据 | 不能断言档案损坏，也没有要求重录来替代排查 |
| 多段向量平均后接近但未达门槛 | 真人同一时刻旁路对比：平均向量 0.7862，保留原音重新提取 0.8045。正式查询改为原音重提取，且不在两种算法里挑高分 | 已修复查询表示；后续真人分数仍不稳定，不能认定准确率问题已解决 |
| 一句长话就耗尽识别机会 | 首句有效时长达到结束条件，尚未取得第二个独立窗口就停止。补上独立窗口计数，同时保留查档次数上限 | 已修复 |
| 疑似换人时已有累计被清空或恢复后少计时长 | 缓存窗口长度与累计证据时长混为一谈。暂存原轨道、保留兼容原音，恢复时新增段只计一次 | 已修复相关累计与计数逻辑 |
| 识别成功后身份反复撤回 | 单句声音分数被当作身份撤回条件。改用已匹配的现场声音作参照，结合连续段数、有效时长和加权分数 | 已部署；已有稳定 0.7 及单句波动回归，真人长期稳定性仍需评估 |
| 已有候选也因一小段低分被隐藏 | 候选显示和确认入口直接受单个 challenger 影响。改为持续证据支持变化时才暂停，单段低分隔离而不直接撤销候选 | 最新真人记录中，0.5245 的单段连续性没有隐藏候选 |
| 普通聊天不主动确认候选 | 仅靠提示词或等待模型调用身份工具，可能一直漏问。改由本地调度，在正常回答后主动插话 | 真人已出现本地主动询问并播放完成的记录；拒绝后停止重试尚未处理好 |
| 还没有候选，后续声音却无法继续累计 | 第一小段声音过早成为固定参照，后续隔离队列反复重置。无候选阶段改为推进有界原音累计；首次产生候选后重新建立连续性参照 | 已部署，回归复现并修复 2.64 秒停滞；最新真人会话首句已有候选，未复现验证这一分支 |
| 本地识别成功，豆包仍说不知道身份 | 动态说明可能反复撤回；`session.updated` 也只证明接口确认。维护当前身份来源，模型使用姓名或记忆前读最新本地工具，并记录实际请求和返回 | 发送、接口确认、工具返回和模型回复分开验证；不能仅凭 ACK 宣称模型采用 |
| 无法定位是哪一句识别或上下文出错 | 补齐稳定轮号、逐轮转写、查档过程、原始控制消息、实际身份上下文、工具结果及导出 | 已上线；旧会话未采集的接口内容不能补造 |
| 未识别的聊天丢弃，或接续时冒充成员记忆 | 所有真实聊天独立归档。未识别时可读设备最近一次聊天，显式标记归属未核实，人工关联与会话身份分离 | 真人记录中归属保持正确，未自动把候选身份变成聊天所有者 |

## 四 已验证与尚未验证的边界

### 自动测试和隔离云端测试

最近一次累计修复通过 198 项相关后端测试，候选参照收尾后重跑 52 项身份及确认测试。此前录入、档案测试、聊天记录及布局相关浏览器测试见各专项文档。不同轮次的测试数量有重叠，不累加为一份准确率样本。

隔离数据库的真实豆包五轮测试验证了普通聊天后主动插话、用户确认、个人记忆读取、纠正和未识别时的设备历史读取。确认和纠正从另一个 SQLite 连接读回；身份来源、实际发送上下文和未自动关联聊天均通过检查。测试使用合成语音和静音播放器，不占用硬件麦克风、扬声器，不修改正式档案，因此不能代替真人声纹准确率或物理播报体验验收。

## 五 自动 tuning 的现状与后续方案

### 已有基础

`identity_match_events` 保存每次查档排序、分数、门槛、分差、拒绝原因、有效时长、质量指标和模型标识；连续性事件保存单段及加权分数、状态和豆包辅助意见。`identity_match_feedback` 追加确认、否认和纠正标签，保留来源及相关成员。

同一匹配事件先确认后纠正，两条原始行都保留；页面标签汇总只计算该事件最新反馈。不能只看汇总数判断历史反馈是否丢失。未标注诊断按最近 5000 条轮换，有人工标签的匹配证据不按这份未标注上限删除。

当前持久化诊断不保存原始录音或查询向量。正式档案保存模板向量；会话音频仅短时驻留内存。现有分数和标签可以用于同一套评分方式的初步分析，但不足以在换模型后重新提取历史声音，也不足以直接生成新的模板。

模型标识当前基于路径和输出维度，另有文件大小及修改时间等信息，不等于模型文件内容哈希。做可复现 tuning 前，需要补齐模型、预处理、模板和策略版本的完整关联。

### 建议的推进顺序 尚未实施

| 阶段 | 计划内容 | 进入下一步的依据 |
| --- | --- | --- |
| 1 建立可信标签集 | 先修复拒绝、打断和自然反馈处理，积累真人明确确认、否认、纠正；模型猜测、未被纠正或话题连贯均不充当正样本 | 标签与实际语句可核对，有跨会话的同人和非本人证据，而不只是单人确认数据 |
| 2 离线评估 | 按成员、会话、有效时长、输入质量分析分数分布，统计误认、拒认、候选确认成功率、换人误判和提问打扰率 | 按会话划分评估集，避免同一场聊天片段同时用于调参与验收；记录采样偏差 |
| 3 离线参数建议 | 用相同留出数据比较查询窗口、连续性规则和候选策略，再决定是否有证据支持调整识别门槛或分差 | 不能仅因平均分低于 0.8 就认定门槛不合理；没有非本人分布，无法判断降低门槛会增加多少误认 |
| 4 旁路试运行 | 新策略只记录“会如何判断”，正式决策继续使用当前策略 | 在相同真实输入上比较误认、拒认、身份切换和打扰率，确认收益没有靠错误采用身份换取 |
| 5 受控上线 | 对通过评估的策略保存版本、限定范围、支持回滚，首批由开发者审核后启用 | 有明确上线和回退条件；先形成可审查的调参报告，再讨论是否允许自动应用 |
| 6 可选的模板自适应 | 另行设计多模板或模板更新流程；需明确采集授权、可信来源、质量条件、模板版本和回退 | 不把一次低分最高名次或单次口头确认直接写回模板；没有原音或合适特征数据时不能声称可训练 |

这些是后续建议，不是已启用的后台任务。本次暂停期间不自动改阈值、不写模板、不启动训练。下一阶段也不以要求用户重录作为默认前提；若未来需要新的校准数据，应先明确数据目的、采集范围、保留方式及授权。

| P2 | 豆包辅助判断的调用覆盖与动态上下文采用 | 以实际工具调用、返回及模型回复核对，不承诺提示词使其每轮必调；本地规则不能依赖云端每次配合 |

| P2 | 儿童、老人和交流障碍场景的体验 | 当前仅有自然语速、允许停顿等原则；趣味引导、不同理解能力、家人协助、多说话者混入等尚无专项真人验收 |
| P2 | 录入进度跨服务重启恢复 | 目前同标签页刷新可恢复，未保存音频/向量仍只在内存；重启和总时限会失效，不宣称永久保留 |
| P2 | 可复现的校准数据和版本体系 | 增加完整版本信息、评估集定义和导出约定；若未来要保存特征或原音，应另行设计授权、访问、删除和保留期限 |

本地声纹身份目前服务于自然称呼和记忆接续，没有活体检测或防录音攻击能力，不作为支付、开锁或访问控制凭据。
