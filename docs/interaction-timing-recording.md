# 模型交互计时记录

设备启动后持续记录 `data/timing/interaction.jsonl`，以及最多 4 个轮转文件
`.1` 至 `.4`，单文件上限约 4 MiB。较早记录达到容量上限后会被覆盖。
新记录不包含提示词、回复正文、音频、姓名或密钥。隐私模式停止记录，
并使旧轮次的迟到计时失效；已经落盘的历史元数据仍保留。

每条记录带 UTC 时间、进程会话编号和单调时钟。模型记录另带请求编号、
模型、语音/文字通道、搜索/直连路径、轮次及可用时的 utterance 编号。

- `model_start`：主问答开始（包括搜索代理内部的等待）。
- `model_first_content`：首段可用正文交给上层的时刻。
- `model_end`：完成、取消或错误；含总耗时、正文增量数、字数和最大增量间隔。
- `voice`：ASR 提交、模型请求/正文、分段提交、合成开始/结束、PCM 就绪、
  输出消费/排空、取消及缓冲指标。用会话编号和 utterance/turn 关联。

搜索代理会先验证工具轮次，因此“首段可用正文”不等于供应商的首个网络
token；总耗时也包含搜索、网络及本地处理。当前记录不能单独拆解每次
供应商请求或搜索工具耗时，也不覆盖后台记忆整理和声纹姓名解析请求。
ASR 提交不是用户开口时刻，不能据此计算完整说话到回复延迟。

日志通过容量为 4096 的非阻塞队列写盘，不在音频线程写文件。
`dropped_events` 表示队列溢出造成的累计丢弃；进程被强制终止可能丢失队列
尾部，只有 start 没有 end 的轮次需视为未完成，不能按成功请求统计。

下次分析时读取板子 `/home/orangepi/lira/data/timing/interaction.jsonl*`，
合并后按会话/请求分组，区分语音与文字、搜索与直连、成功与取消/错误，
再统计首段正文和总耗时的中位数、P95、异常轮次，以及合成 RTF 和播放等待。
记录开始前的历史对话无法从这里恢复。日志已满会覆盖旧数据，需长期保留时
应先复制这组文件。
