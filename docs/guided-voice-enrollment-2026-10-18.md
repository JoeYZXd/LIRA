# 声纹档案页引导录入

入口：开发者控制台 → 声纹档案 → 添加。录音来自 LIRA 板子的生产麦克风流，不是浏览器麦克风，不调用本地 ASR、豆包或 Jev，不产生语音 API 费用。

## 录入协议

填写姓名与称呼，明确同意采集；停止当前对话并独占开发测试窗口。四段不同的日常口语文案，每段至少 8 秒按能量检测计算的有效语音，总计至少 32 秒。自然语速、平常音量与日常使用距离，不要求人工制造快慢、轻重、喊叫或耳语。每段最多 40 秒；不足、削波或与先前声音不一致时只重录本段。年龄不改变匹配门槛，允许慢读、停顿、先熟悉文案后复述。家人帮助应在点击录音前完成，避免混入其他说话者。

使用不同内容与独立验证，避免仅记住同一口令的阅读条件。32 秒是本项目采集目标，不是准确率承诺；有效语音目前使用能量检测，不等同于语义 VAD，也不验证逐字朗读或防录音攻击。参考 Microsoft 的[文本无关声纹说明](https://learn.microsoft.com/en-us/rest/api/speakerrecognition/)以及 AWS 历史声纹系统的[30 秒净语音采集经验](https://docs.aws.amazon.com/connect/latest/adminguide/voice-id.html)（AWS Voice ID 已停止支持，仅作历史协议参考）。

每段取裁去首尾静音后的前 10 秒，使用现有本地模型提取向量。首段作为初始参考，此后各段只与此前已保留向量的归一化平均模板比较，比较时不把当前段混入参考。达到配置 consistency_threshold（当前 0.85）为普通采集段；介于 assign_threshold（当前 0.73）与 0.85 之间为临界段，保留并继续，同时在页面汇总中持续标记；低于 0.73 或向量维度不符时要求重录当前段。0.73 仅复用既有弱关联阈值作暂定异常线，没有经过针对性校准，不是身份确认线，也不改变日常识别配置。短音、失真、非有限音频、无效向量等质量闸仍保留。

四段保留向量采用固定等权归一化平均形成最终模板，临界段同样参与，不挑最高分或在验证失败后重新选择模板。第五段是独立留出验证，不加入模板。仍按当前生产配置的匹配门槛（0.80）以及与其他档案的分差（0.10）检验，通过后才允许点击保存。姓名或声纹重复时显示冲突对象，可以改名或明确选择替换；未经选择不覆盖任何已有档案。验证失败可以重试第五段，也可以取消后重新开始，不自动降低身份匹配门槛。

## 安全与生命周期

请求沿用控制台会话认证。随机录入 token 隔离多标签页；变更操作串行，整个引导期间占用 dev_mutex。明确放弃、隐私开启、10 分钟总时限会清除内存并释放设备。暂时关闭和页面刷新不再取消录入，浏览器同一标签页的 sessionStorage 仅保留恢复 token，音频和向量始终只在服务内存中；页面离开时尽量停止当前录音并保留结果。服务重启与 10 分钟总时限仍会使恢复 token 失效，关闭期间继续占用引导测试窗口，页面明确说明此限制。单段超过 40 秒直接丢弃，采集输入中断也丢弃本段。正式档案仍只保存声纹向量、姓名和称呼。最后保存采用原有原子注册接口。

## 验证范围

自动测试覆盖独立验证前禁止保存、验证录音不参与模板、失败与重试、短音拒绝、隐私取消与锁释放。真实用户在板端完成朗读后才能评价其实际识别效果；页面上线或合成测试不能证明特定用户识别已经成功。

## 第三段看似卡住的修复

拒绝录音时接口原本只在错误响应里返回原因，没有更新引导状态中的 message；下一次每秒状态查询因此把错误覆盖为旧的“正在录音”。浏览器回归测试已复现错误出现后 2.2 秒消失。现在将拒绝原因保存在会话状态，持续显示有效语音时长或与各已通过段落的一致性分数，保留原有门槛与已通过段落，同时写入不含姓名、token、原音或向量的拒绝日志。此前实际第三段拒绝原因未留日志，不能据此断言用户读音有问题。

轮询不再占用动作 busy 标志或禁用按钮；通过动作修订号丢弃晚到的旧状态响应，避免点击被忽略或旧快照覆盖新结果。新增第三段拒绝、跨轮询保持错误、重录后继续第四段的真实浏览器回归，连同两个视口完整流程共 3 项通过；后端相关 69 项通过。本次服务重启会丢弃旧的未完成会话，已保存档案不受影响。

## 冲突处理与档案管理

采集完成后显示重复姓名/相似声音所属成员，允许修改保存姓名与称呼，或者明确选择替换对象。改名不解除相似声音冲突。用户选择替换后，仅该目标的旧声纹从独立验证的竞争档案中排除，其他档案仍按原门槛/分差检查；同一份留出验证向量重新计算结果，不必因改名或选择替换重读，验证向量始终不加入模板。点击“替换并保存”才在单一事务中更新成员姓名、称呼、声纹，保留成员 ID 与聊天记忆。

列表增加“重新录制”和“删除声纹”。重新录制预填原姓名/称呼与替换目标，取消、失败均不修改旧声纹。删除须明确确认，只删除 voice_profiles 中该成员的向量，保留成员、称呼与聊天/个人记忆；无声纹的成员可再次录制。操作沿用控制台会话、隐私闸与测试互斥，删除会停止当前对话以清除会话身份；档案版本指纹防止覆盖或删除已被其他操作更新的档案。原有语音工具的 register_voice 行为不变，替换仅开放于明确确认的控制台流程。

相关后端 95 项及新增删除确认/隐私/录音占用检查通过，浏览器 4 项通过，包含添加冲突 → 选择替换 → 保存、重新录制取消、删除后成员聊天保留。真实板端验证只做读操作与 begin/status/cancel，不替用户实际删除或替换档案。

## 确认后未保存与关闭丢失修复

原前端“应用姓名与保存方式”只发 resolve，需要第二次点击 save；用户确认替换后以为已保存，关闭按钮又发送 cancel 清除了内存。浏览器回归已复现“确认替换后弹窗不关闭、档案未保存”。现在有验证结果时按钮直接标为“确认修改并保存”，确认后 resolve 返回通过且无冲突则立即调用 save；普通保存按钮也先应用当前编辑字段，避免按旧姓名保存。只有服务返回 saved 才显示成功，失败保留会话。尚未独立验证时按钮标为“应用修改，继续独立验证”，不会提前保存。

普通关闭改为“暂时关闭（保留进度）”，清除必须另点“放弃本次录入”并明确确认。同标签页刷新可恢复；上述总时限和隐私条件仍适用。5 项浏览器测试覆盖一次确认替换保存、最终姓名生效、临界提示、关闭后恢复、刷新后恢复四段录音及独立验证结果、明确放弃和删除。仅热更新模板与脚本，不重启服务；生产检查只读，不操作真实档案。
