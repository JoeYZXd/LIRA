# LIRA 设备开发者控制台（远程状态监控 / 配置 / 独立测试）

## Summary

在现有设备 UI（局域网 8080）内新增口令保护的开发者区块：v1 提供整机状态总览、运行参数配置、语音/视觉/同步三大链路的独立触发测试与运行日志查看，严格服从隐私联锁；实时音视频流明确不做（Phase 2 候选）。

---

## Problem Frame

M7 主循环接线已完成（2026-10-03），设备进入板上实机验证阶段。当前唯一调试手段是 SSH + journalctl + 人站在设备旁听喇叭、说话术——冒烟清单（SETUP.md 2.9）的每一项都要物理在场才能验证：听不见 TTS 是否出声就得凑到喇叭跟前，OCR 好坏得跑过去看，同步是否生效得翻日志。单设备 bring-up 期的迭代成本被"必须在场"放大。

同时，设备已有两张 web 面（老人设置 UI、家属管理后台），但都不承载"把某个链路单独拉出来打一枪"的调试语义：老人面刻意保持极简，后台属于家属域。缺的是一个面向开发者自己的、能把状态看全、把功能拆开单测的远程面。

---

## Actors

- A1. 开发者（设备维护者）：控制台主要用户，从局域网内另一台机器访问；bring-up 与后续远程运维的执行者。
- A2. 老人用户（设备旁）：不使用控制台，但受其隐私联锁与操作播报影响（如测试触发 TTS 出声）。
- A3. 家属（后台侧）：不使用控制台；其配置的隐私开关状态决定控制台采集类功能是否可用。

---

## Key Flows

- F1. 视觉链路独立测试
  - **Trigger:** 开发者在控制台点击视觉测试
  - **Actors:** A1
  - **Steps:** 鉴权检查 → 隐私联锁检查 → 单帧拍摄 → OCR（det/rec）→ 返回识别文本与分阶段耗时
  - **Outcome:** 开发者不接触设备即可评估拍摄→OCR 链路质量与时延
  - **Covered by:** R10, R14, R15
- F2. 隐私联锁拒绝
  - **Trigger:** 隐私模式 ON 时请求采集类测试（麦克风录音 / 拍摄）
  - **Actors:** A1（发起），A3（隐私状态来源）
  - **Steps:** 联锁检查 → 拒绝执行 → 返回明确原因提示
  - **Outcome:** 无任何采集发生；控制台结构性不构成监视口子
  - **Covered by:** R15, AE1/AE2
- F3. 整机场景回放
  - **Trigger:** 开发者点击"模拟唤醒→指令"回放
  - **Actors:** A1；A2（若在旁会听到设备播报）
  - **Steps:** 注入唤醒事件 → 注入指令文本 → 状态机按真实链路执行 → 展示迁移记录与播报
  - **Outcome:** 不说话即可验证状态机全链路行为
  - **Covered by:** R12, AE5

---

## Requirements

**状态监控与日志**
- R1. 状态总览：对话状态机当前状态、音频路由、同步连接状态与 (epoch, version) 回执、远程可用性（联网 + 熔断）、语音栈/OCR 就绪性，一屏可见
- R2. 状态数据保持可编程读取（既有只读状态 JSON 语义延续，kiosk 轮询不破坏）
- R3. 运行日志查看：展示最近事件日志；项目日志纪律天然保证内容只有事件与耗时（识别文本/播报内容永不入日志）
- R4. 配置在线修改：音量、语速（既有运行时设置在控制台内可达）；日志级别在线调整

**独立测试**
- R5. 语音链路——TTS 播报：指定文本送真实 TTS 出声（文本仅在请求/响应中出现，不落日志）
- R6. 语音链路——麦克风录音：录制固定时长（约 10s）并回放；受隐私联锁约束
- R7. 语音链路——识别与意图：用上一步录音或上传音频，返回识别文本与意图分类结果（结果仅在响应中返回，不落日志）
- R8. 视觉链路：单帧拍摄 → OCR → 返回识别文本与分阶段耗时（拍摄/det/rec）
- R9. 同步测试：手动触发后台快照拉取，显示应用结果与 (epoch, version)
- R10. 整机场景回放：模拟唤醒 + 注入指令文本，经真实状态机执行，展示状态迁移与播报记录
- R11. 红外测试暂缺：M5（BroadLink 到货）后加入学习/发射/码表查看

**安全与联锁**
- R12. 开发者区块整体经设备口令 vault 鉴权；口令未设置时 fail-closed（引导设置，无任何测试可达）
- R13. 隐私严格联动：隐私模式 ON 时，采集类测试（R6/R7/R8）一律拒绝并返回原因提示；TTS 播报类（输出型）不受限
- R14. 开发者区块可经配置整体隐藏（产线部署默认关闭：无入口、路由不可达）
- R15. 控制台全部操作写入事件日志并带来源标记（dev-console），便于审计与回归排查

---

## Acceptance Examples

- AE1. **Covers R6, R13.** Given 隐私 ON，when 请求麦克风录音测试，then 请求被拒绝并返回隐私开启提示，且无任何采集发生。
- AE2. **Covers R8, R13.** Given 隐私 ON，when 请求视觉测试，then 拒绝；Given 隐私 OFF，when 请求视觉测试，then 返回 OCR 文本与分阶段耗时。
- AE3. **Covers R12.** Given 设备口令未设置，when 访问开发者区块，then 引导至口令设置，测试功能全部不可达（fail-closed）。
- AE4. **Covers R7, R15.** Given 上传一段"打开台灯"录音，when 识别测试执行，then 响应返回识别文本与家电-打开意图；日志中不存在该文本。
- AE5. **Covers R10.** Given 整机回放执行"唤醒→打开台灯"，when 完成，then 状态机迁移记录（STANDBY→LISTENING→EXECUTING→STANDBY）与播报记录在控制台可见。
- AE6. **Covers R14.** Given 配置关闭开发者区块，when 访问 8080 首页，then 无开发者入口且对应路由不可达。

## Success Criteria

- SETUP.md 2.9 冒烟清单中可独立触发的项目，全部能在控制台完成验证，开发者无需物理在设备旁（F1/F3 的直接产出）。
- 隐私联锁（AE1/AE2）进入设备测试套件成为回归项——控制台的存在不得弱化隐私模型。
- 关闭区块后，设备 UI 与 U7 交付时行为等价（AE6），产线形态不被调试功能污染。

---

## Scope Boundaries

- 实时视频流 / 实时音频流：明确不做（隐私敏感 + 摄像头需先打通 ISP 路径）——Phase 2 候选
- 红外测试：M5 硬件到货后随 RM4 一并加入
- config 文件级参数（设备号/模型路径/LLM 端点等）的在线修改：仍走 config.yaml + 重启
- 远程进程重启 / systemd 管理 / OTA：运维面演化方向，v1 不做
- 公网可达：维持项目 Phase 1 边界（仅局域网；远程场景走 VPN 回家，属部署文档而非控制台功能）
- 多设备管理：单设备项目

---

## Key Decisions

- **并入现有设备 UI（8080）而非独立服务**：复用口令 vault 与既有装配模式，零新增攻击面/端口；接受"调试区块与老人设置同进程"的耦合，以 R14 区块隐藏作为产线保险（用户决议，推翻了独立服务建议）
- **v1 砍掉实时音视频流**：摄像头现路径为慢速单帧（实时视频需打通 ISP），实时听麦是隐私模型最敏感的口子；按需单帧 + 录音回放已覆盖 bring-up 痛点（用户确认）
- **隐私严格联动（fail-closed）**：采集类测试在隐私 ON 时结构性拒绝，控制台不构成绕过隐私承诺的旁路（用户确认）
- **定位 = 先开发用、逐步演化**：不为长期运维面过度打磨；鉴权与联锁是底线，打磨项从简
- **识别文本/播报文本只在请求-响应往返中出现**：延续日志纪律，控制台不新增内容落盘面

---

## Dependencies / Assumptions

- 摄像头为裸 Bayer 单帧路径（每次拍摄起子进程、秒级）：R8 的耗时统计将如实包含该开销；实时流所需的 ISP 打通不在本期
- 整机场景回放复用既有整机装配形态（与 e2e 同构），不为控制台新写一套驱动
- IR 测试依赖 M5（BroadLink RM4）到货
- 局域网明文 HTTP 为项目既有接受边界（与残留评审记录的 UI 硬化债同源，本控制台不改变该边界但扩大其暴露面价值——口令鉴权为必备项）
