# 电视至LIRA的直接回调网络预检

本检查发生在新回调服务实现前，使用既有HTTP服务验证反向连通性；不代表新回调协议已经验收。

- LIRA：192.168.101.26/24，网关192.168.101.1，设备服务监听0.0.0.0:8080。
- 电视：192.168.3.25/24，Android策略路由经192.168.3.1。
- 电视访问http://192.168.101.26:8080/status超时；ICMP也无响应。没有把仅ICMP失败作为结论。
- LIRA向电视40100建立TCP连接时，本地源地址192.168.101.26，电视/proc/net/tcp6看到对端为::ffff:192.168.3.7。由此实际证实连接途中发生源地址转换。
- 当前现象与下级网段经192.168.3.7出站NAT、电视无法直接访问下级地址一致；监听地址错误已排除，尚无路由器防火墙配置读取证据。

用户选择让电视接入LIRA所在路由器的局域网。已用现有ADB打开电视Wi-Fi设置，等待连接后的192.168.101.x地址。未修改路由器、主机防火墙、服务端口或既有配对密钥；没有采用事件拉取代替用户要求的直接回调。

后续需在同网段重新检查HTTP连通性，再配置已配对电视与LIRA回调地址，并以真实课级完成事件证明反向通知和事务计数。
