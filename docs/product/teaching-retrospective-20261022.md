## 2. 可以固化到后续功能的做法

### 从事实到判断，再到固定执行

教材和核对结果属于事实层；模型依据 skill 做教学判断；后端验证后冻结任务，电视执行固定状态机。这条边界避免模型在每一个播放步骤即兴决定流程，也让更换模型或 TTS 不影响孩子的操作约定。新学科先定义它自己的任务合同和事实类型，再接共享能力。

### 音频按四层验收

1. **源资源**：合成完整结束、字节/采样格式有效、长度与 SHA256 一致，必要时检查 RMS 与峰值。云端已认可参数不再叠加旧本地归一化。
2. **播放器**：预填充、启动、完整写入、播放头排空与保护尾部；切词时隔离旧播放器和迟到回调，失败有明确回执。
3. **物理输出**：确认输出路由、电视静音与音量；设备麦克风受回声处理影响，不当作唯一验收手段。
4. **教学听感**：人耳试听完整词、第三声、前后鼻音、语速和重复后的舒适度。帧数匹配不能替代这一层。

Qwen3-TTS 在本板 CPU 路径两词合成约 31–36 秒、峰值内存约 5.20 GiB，这些是该实验条件下的实测，不推广为所有硬件结论。当前采用用户试听认可的豆包参数；Qwen 没有成为生产依赖。

### 长流程测生命周期，演示只运行一次

单次长流程覆盖准备、澄清、分页、重播、暂停、解释、恢复、结果核对及知识回流；断线/重载/播放失败等用受控故障验证。故障后优先续接同一任务；结束即停止，不用循环演示掩盖失败。另用隔离回归覆盖缓存容量与终态释放，不通过生产家庭反复建任务来测试容量。

### 三种界面证据各负其责

H5 用于快速审阅颜色、文案、字号和遥控语义；宿主 Java 测试负责状态与键位；原生真机负责 Android 字体、固定布局、遥控与物理声音。报告分别标注，不能用 H5 截图或模拟 AudioContext 结束替代实机证据。

### 日志对齐任务，学习事实保持可信

日志围绕 task_id、项目、事件序号、播放回执和版本关联。电视显示安全摘要，管理页含家长可查的详细任务；密钥、配对令牌及家庭完整数据库不放进公开凭据。演示保持未核对，保存照片不等于全对，等待时长不等于书写速度。

## 3. 下一次开发的复用检查

- 先确认新能力是教学规则、执行机制还是展示能力；参考 [PRD 的 B1–B9](teaching-prd.md#21-可供其他功能复用的基础能力)，避免复制一份默写服务后改名。
- 复用成员、教材、skill 版本、音频和电视连接时，定义新业务合同及能力协商；当前带 dictation 的实现不自动成为任意活动框架。
- 配置保存冲突、旧任务版本不变、重试幂等、暂停真实回执、旧回调隔离、终态清理都纳入定向回归。
- 新音色先做小样；新电视布局同时检查日志开/关、最长文案和遥控可达性；再做一次有边界的真实演示。
- 结果报告分别写“实现完成”“验证过什么”“未验证什么”；产品阶段完成由用户确认，不反向改写历史失败报告。
